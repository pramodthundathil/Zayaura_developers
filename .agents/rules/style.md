# Interior Design & Architecture Website — Development Rules

## 1. Project Objective

Create a premium, modern, visually immersive website for an **Architecture & Interior Design company**.

The website should communicate:

* Architectural expertise
* Interior design capabilities
* Creativity and craftsmanship
* Premium project quality
* Professionalism and trust
* Design-build capabilities
* Completed project portfolio
* Ability to handle residential and commercial projects

The final website must feel like a **premium architecture/design studio**, not a generic business website.

---

# 2. Technology Requirements

Use only:

* HTML5
* CSS3
* Bootstrap 5.x
* Vanilla JavaScript
* Bootstrap Icons or Font Awesome
* Google Fonts

Do NOT use:

* React
* Vue
* Angular
* Tailwind CSS
* jQuery unless absolutely required
* Heavy UI frameworks
* Unnecessary libraries

The website must be easy to deploy on standard web hosting.

---

# 3. Design Direction

Use a sophisticated architectural design language.

### Visual Style

The design should be:

* Minimal
* Elegant
* Premium
* Editorial
* Architectural
* Spacious
* Image-focused
* Modern
* Sophisticated

Avoid:

* Overly colorful layouts
* Cheap-looking gradients
* Excessive rounded cards
* Excessive shadows
* Generic Bootstrap appearance
* Too many animations
* Cluttered sections
* Stock-template appearance

The website should resemble a **high-end architecture/interior design studio website**.

---

# 4. Color System

Use a restrained luxury palette.

Suggested colors:

```css
--primary: #1C1C1C;
--secondary: #F4F1EC;
--accent: #A4865A;
--text: #2B2B2B;
--muted: #777777;
--white: #FFFFFF;
--border: #E5E2DC;
```

Use the accent color sparingly.

The primary visual emphasis should come from:

* Photography
* Typography
* Whitespace
* Layout
* Architectural geometry

---

# 5. Typography

Use premium fonts.

Recommended:

### Heading

* Playfair Display
* Cormorant Garamond
* DM Serif Display

### Body

* Inter
* Manrope
* Montserrat

Use a maximum of **two font families**.

Typography should have:

* Large editorial headings
* Strong hierarchy
* Comfortable line height
* Proper letter spacing
* Responsive font sizes

# 20. Responsive Design

The website MUST be fully responsive.

Test:

### Desktop

* 1920px
* 1440px
* 1280px

### Tablet

* 1024px
* 768px

### Mobile

* 480px
* 390px
* 375px

* Horizontal scrolling
* Overflowing text
* Broken images
* Overlapping sections
* Navigation overflow
* Buttons outside viewport

Use:

* Full-width images

* Touch-friendly buttons
* Proper spacing
* Sticky CTA where appropriate

Minimum touch target:

```text

```

# 22. Images

Architecture/interior photography is a primary design element.

Use:

```html
<img>
```

with:

```html
loading="lazy"
```

for non-critical images.

Every image must have meaningful:

```html
alt=""
```

Do not use unrelated stock images.

Use placeholders such as:

```text
assets/images/projects/project-01.webp
```

until actual images are supplied.

---

# 23. Image Aspect Ratios

Maintain consistent image composition.

Recommended:

### Hero

16:9 / 21:9

### Project cards

4:3

### Portrait projects

3:4

### Gallery

4:3 / 3:2

Do not distort images.

Use:

```css
object-fit: cover;
```

where appropriate.

---

# 24. Animations

Animations should be subtle.

Use:

* Fade-up
* Image reveal
* Scale on hover
* Smooth navigation
* Parallax where appropriate
* Project image hover effects

Avoid:

* Excessive bouncing
* Continuous animations
* Spinning elements
* Distracting transitions

Animation duration:

```css
300ms - 800ms
```

Use CSS transitions wherever possible.

Respect:

```css
prefers-reduced-motion
```

# 27. Performance

The website should load quickly.

Requirements:

* Optimize images
* Prefer WebP/AVIF
* Lazy-load below-the-fold images
* Minimize unnecessary JavaScript
* Avoid large libraries
* Use CSS efficiently
* Preload critical hero image where appropriate
* Avoid layout shifts

Target:

* Fast initial load
* Good Lighthouse performance
* Mobile-friendly performance

---

# 28. Accessibility

Follow basic WCAG principles.

Ensure:

* Sufficient color contrast
* Keyboard navigation
* Visible focus states
* Proper form labels
* Alt text
* Semantic HTML
* Accessible navigation
* ARIA only where necessary

Do not rely only on color to communicate meaning.
